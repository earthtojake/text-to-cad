# Posts: the G-code dialects

A post turns each setup's toolpaths into one program for a controller, written beside the part as
`<part>.<setup id><extension>`; a GRBL mill or router setup that uses more than one tool is one program per tool,
`<part>.<setup id>.T1<extension>`, `.T2`... (run them in order, zeroing Z with each tool). Pick it with `machine.post`, or let a `machine.model` name its
controller's. Left out of both, the plan takes the kind's usual dialect, lists it as assumed and
says so in every file's header: tell the user, and ask which controller runs the machine
([job-file.md](job-file.md) has the machine keys every post shares). Tell the
user which file runs first, and how the part is re-held between setups. The keys below are the
post's own: put them in `machine` next to `kind` and `post`; a key another post takes is refused.

```json
{"machine": {"kind": "lathe", "post": "fanuc", "cycles": true, "program_number": 2001}}
```

```
cadgen cam plan part.step --job job.cam.json
```

## The safety header

Every program opens with comments: the part, setup and post; generated by cadgen; NOT proven on a
machine, air-cut it or run it single-block first; what to verify for the machine (the work offset and every
tool length on a mill, every tool's offsets on a lathe, the focus on a laser, the torch or nozzle heights on
a cutting table, the start hole on a wire EDM; Marlin: the origin is where the head starts); units mm,
feeds and speeds are starting points; on a GRBL file per tool, which file it is and which tool to load and
zero; the material and every tool with the speeds it runs at (`T1: 6 mm flat: 13260 rpm, feed 1591 mm/min,
plunge 477 mm/min`); for a fine bore that shifts its bar, or a back bore, which way the bar's tip must point
at the spindle's orient position. Then the post's own notes (diameter or
radius X on a lathe, how a 3+2 setup is set up, TCP, how a wire's offset is carried). Nothing sends a
program to a machine. Tell the user this line when you report.

## The posts

| post | file | kinds | what it writes | its machine keys |
| --- | --- | --- | --- | --- |
| `grbl` | `.nc` | mill, router, laser | no tool changer and no tool table: one file per tool, each starting `G0 Z<clearance>` before the spindle; never `G28`, `G30` or `G53` (the machine may not be homed); `G4 P` spin-up after every spindle start; cycles expanded, a tap, a shifting fine bore and a back bore refused (no spindle-synchronised feed, no oriented stop); coolant `M8` flood only, mist and air a comment to switch them by hand (stock GRBL has no M7; on a laser air assist is `M8`); laser pierce in `M3 S` then cut in `M4 S` (0-1000); dwell in seconds; lines kept to 79 characters of code, 127 in all. Check: `$32=0` on a mill (in laser mode GRBL does not stop for `M3`/`M5`), and zero Z again on each tool's file | `spindle_spinup_s` |
| `linuxcnc` | `.ngc` | mill, mill4, mill5, lathe | `G91.1`, `G64 P` blending, `G49` then `G53 G0 Z0` before `T M6` (and at the end; needs a homed machine), `G43 H`, G81-G89 (tap as rigid `G33.1`, or its floating `G84`/`G74` for a tap with `rigid: false`; the `G73`/`G83` clearance is LinuxCNC's own 0.254 mm), fine bore and back bore as moves with `M5` and `M19 R0 Q10` before each shift, air a by-hand comment, `M2`; lathe `G7`/`G8`, `G30` before each turret index (set it with `G30.1`), `G96 D S`, `G95`, one-line `G76`; roughing always expanded | `cycles` |
| `fanuc` | `.nc` | mill, mill4, mill5, lathe | `%` + `O` number (one per setup), upper-case comments, decimal points on every coordinate (a Fanuc without parameter 3401 reads `X10` as 10 micrometres), `G91 G28 Z0.` before `T M6`, G73-G89 with `M29` rigid tap (some controls want `M29` before `M3`: check; none for a tap with `rigid: false`, a floating holder), fine bore `G76 Q` and back bore `G98 G87 Q` (`P` its dwell) (the shift direction is a parameter, assumed +X; any other shift posts as moves with `M19`), dwell ms, air a by-hand comment, `G49` at the end, `N` numbers with `line_numbers`, 3+2 `G68.2`/`G53.1`, TCP `G43.4`; lathe `T0101`, `G50 S` + `G96`, `G98`/`G99`, two-block `G76`, `G71` with `cycles` | `cycles`, `program_number` |
| `haas` | `.nc` | mill, mill4, mill5, lathe | as Fanuc, plus `N1 T1 M06`, `N2`... at each tool change (restart at a tool), rigid tap without M29 (rigid tapping is an option: check it is installed; the same G84 with a floating holder), fine bore `G76 I J` along the shift, the back bore as Haas's `G77 I J` (not `G87`, another cycle on a Haas; G77 takes no dwell, so a back bore with one posts as moves with `M19`), dwell `P` in milliseconds with no decimal point (with one Haas reads seconds), air `M83`/`M84`, 3+2 by `G254` dynamic work offset, TCP `G234`, `G187` smoothing; lathe `T101`, one-block `G76 X Z K D F A` and `G71 P Q U W D F` | `cycles`, `program_number`, `smoothing` |
| `mach3` | `.tap` | mill, mill4, router, plasma | `G91.1` (incremental arc centres), `G0 Z<clearance>` in the work offset before `T M6` and at the end, never `G53` (many Mach3 machines are never homed, so machine Z0 may stand below the work; `homed: true` posts `G53 G0 Z0`), `G43 H`, G73-G89 (G84 does not follow the spindle: a floating holder; a tap with `rigid: true`, a left-hand tap, a shifting fine bore and a back bore refused), `G49` at the end, dwell in seconds (turn Mach's "G04 dwell param in ms" off, or set `dwell_ms`; set its spin-up delay too); plasma torch `M3`/`M5` with heights | `cycles`, `dwell_ms`, the torch keys (THC off by default) |
| `marlin` | `.gcode` | laser | `G21 G90`, `M3`/`M4 S` on Marlin's scale, `G4 P` ms, air assist `M8`/`M9`, ends `M5` (Marlin's M30 deletes a file), no work offsets: `G92 X0 Y0` makes the origin where the head starts | `laser_scale`, `laser_mode`, `inline_power`, `z_words` |
| `plasma` | `.nc` | plasma | per cut: pierce height, `M3`, pierce delay, cut height, THC on; then THC off, `M5`, safe height; `M30` | the torch keys, `dwell_ms` |
| `waterjet` | `.nc` | waterjet | per cut `M3`, pierce dwell, `M5`; X Y only; `M30` | `pierce_s`, `z_words`, `dwell_ms` |
| `wire_edm` | `.nc` | wire_edm | `%` + `O`, `G92 X Y` at the first start hole, `G40` (offsets applied), thread/cut codes between start holes, taper `G51`/`G52 A` + `G50`, `M30` | `wire_comp`, `uv_words`, `wire_thread`, `wire_cut`, `program_number` |

## The machine keys

| key | posts | values (default) | what it changes |
| --- | --- | --- | --- |
| `cycles` | linuxcnc, fanuc, haas, mach3 | `true`, `false` (left out) | left out: drilling and threading cycles are canned cycles, lathe roughing is plain moves; `true`: every cycle the controller has (Fanuc/Haas `G71`); `false`: every cycle as plain moves |
| `program_number` | fanuc, haas, wire_edm | 1 to 9999 (99999 Haas) (1000) | the first setup's `O` number; each next setup is one more, so two setups never share one |
| `line_numbers` | fanuc | (`false`) | `N10`, `N20`... on every block |
| `homed` | mach3 | (`false`) | the machine is homed: `G53 G0 Z0` (and `G53 G0 A0`) before tool changes and at the end |
| `smoothing` | haas | `off`, `rough`, `medium`, `finish` (`off`) | `G187 P1`..`P3 E<tolerance>` |
| `dwell_ms` | mach3, plasma, waterjet | `true`, `false` (`false`) | `G4 P` in milliseconds (Mach's "G4 dwell in ms" setting) |
| `torch_z` | mach3, plasma | (`true`) | write the torch heights as Z moves |
| `pierce_height_mm`, `cut_height_mm`, `safe_height_mm` | mach3, plasma | mm (3.8, 1.5, 10) | the torch heights |
| `z_feed_mm_min` | mach3, plasma | mm/min (1000) | the feed down to cut height |
| `pierce_delay_s` | mach3, plasma | s (0.5) | the pierce delay when the operation gives none |
| `thc`, `thc_on`, `thc_off` | mach3, plasma | (`false` on mach3, `true` on plasma), (`M101`, `M102`) | torch height control around each cut; the codes are placeholders: set your controller's |
| `spindle_spinup_s` | grbl (and every post as a shared machine key) | s (3 on GRBL, else none) | the dwell after a spindle start from standstill, or a restart after a stop, before the tool cuts; not after a reversal. The cycle time counts it |
| `pierce_s` | waterjet | s (1) | the pierce dwell when the operation gives none |
| `laser_scale` | marlin | `255`, `1000` (255) | the S value of full power |
| `laser_mode` | marlin | `constant`, `dynamic` (`constant`) | `M3`, or `M4` (power with speed, Marlin 2.1+) |
| `inline_power` | marlin | (`false`) | `M3 I` inline mode: `S` on every cutting move, `S0` on the next rapid |
| `z_words` | marlin, waterjet | (`false`) | post the toolpath's Z |
| `wire_comp` | wire_edm | `applied`, `controller` (`applied`) | applied: the path is the wire centre, `G40`; controller: `G41`/`G42 D1` per cut, D1 holding only a wear or skim adjustment |
| `uv_words` | wire_edm | (`false`) | taper as explicit `U V` words (lite: the lean turns over the move after a sharp corner) instead of `G51`/`G52 A` |
| `wire_thread`, `wire_cut` | wire_edm | (`M60`, `M50`: Fanuc-format AWT) | the thread-the-wire and cut-the-wire codes (builders differ: check the control's manual); the wire is cut only when the table travels to another start hole |

## What every post does for safety

- **The first move after a tool change** (and the program's first): Z is at the top (`G91 G28 Z0.`, `G53 G0 Z0`,
  Haas's own M06; GRBL's file starts `G0 Z<clearance>`), the rotary axes turn first, then `G0 X Y` over the first
  point, then the tool length at the clearance height (`G0 G43 Z H`; under TCP `G43.4 H`/`G234 H` comes after
  the rotary axes and before X Y), then down. A lathe moves X, then Z. A cutting head with Z words goes up
  first too (a plasma torch to `safe_height_mm` after the work offset; a GRBL laser, or a Marlin or waterjet
  with `z_words`, to the clearance height): where it starts is unknown, and an X Y rapid at the cut height
  drags it through tipped-up parts.
- **Tool changes** on ISO mills stop the spindle and coolant first (`M5 M9`); the coolant comes back on after.
  A **stop** (`M0`/`M1`) switches the spindle and coolant back on before the next move.
- **Rotary turns**: a rapid that turns a rotary axis below the clearance height is refused; under TCP it is
  refused straight out of a cut (below the retract height), since it would swing the tool through the part.
- **Arcs** shorter than the posted resolution post as lines (never as a full circle); an arc whose end is off
  its circle is refused. Arc fitting keeps every point and every chord within the tolerance, merges a
  straight run into one line, fits a helix as one `G2`/`G3` with Z where the post takes helical arcs, and
  never folds a ramp into a helix.
- **Depths** never come out deeper than planned: a cut's Z rounds up at the post's precision, a canned
  cycle's depth toward its R plane.
- **Spindle**: a speed that would post as `S0` is refused; a tap feeds at the posted `S` times its pitch.
- **Coolant** a controller has no code for is a comment telling the operator to switch it on or off by
  hand, never another coolant's code.
- **Numbers**: a coordinate that is not a number, or a feed that is not positive, is refused naming the move.
- **Comments** keep letters, digits, spaces and `. , : / + - _ = * # ' "` only: GRBL reads `!` (feed hold),
  `~` (cycle start), `?` and bytes of 0x80 and up as realtime commands even in a comment. `%` is written
  "percent", `;` a comma, and they wrap at 70 characters.
- **The end**: `M5`, `M9` once, Z home (Mach3: the clearance height), then a table a 3+2 setup or TCP program
  turned back at rotary zero (`G91 G28 A0. C0.` on Fanuc/Haas, `G53 G0 A0 C0` on LinuxCNC, `G0 A0` on Mach3),
  and the tool length cancelled (`G49`).

## Multi-axis and lathes

- **3+2** (a tilted setup): LinuxCNC and Mach3 turn the table (`G0 A.. C..`) after each tool change: set
  the setup's work offset on the turned part. Fanuc enters a tilted working plane (`G68.2 X0 Y0 Z0 I J K`,
  `G53.1`, out with `G69`) and Haas a dynamic work offset (`G254`, out with `G255`): there the work offset
  is the setup's origin on the part with the table at zero.
- **Simultaneous** (rotary axes change from move to move, while cutting or indexed between passes: the
  moves are the tool tip at rotary zero): A/B/C on every move, no arc fitting, tool length as tool centre
  point control (`G43.4`; Haas `G234`), drilling posted as plain moves (no canned cycle under TCP). Stock
  LinuxCNC has no `G43.4`: it needs a TCP kinematics configuration that provides it (the header says so).
  Mach3 has no TCP: such a program is refused there.
- **Lathe**: X is a diameter (radius with `machine.diameter_mode: false`), arcs are `G18` with I a radius.
  Constant surface speed posts with its rpm clamp; feed per revolution where the operation asks.
  Threading is the controller's `G76`; a tapered thread posts as plain moves on LinuxCNC. A lathe never
  gets `G90` from Fanuc or Haas (it is a turning cycle there).

## Refusals

What the controller cannot do for an operation is a `no_post_support` error on that operation: no G-code
is written, the plan and its GLB stand, and the summary says what to change (another post, or the
operation): a tap on a post that cannot hold the feed to the spindle (GRBL, `cycles: false`, under TCP,
a left-hand tap on Mach3, a rigid tap (`rigid: true`) on Mach3), a fine bore that shifts its bar or a
back bore on a controller that cannot orient its spindle (Mach3, GRBL), a TCP program on Mach3, a
spindle speed that would post as `S0`. A program the machine
cannot run at all is refused in one sentence, and nothing is written: a beam on a mill,
a spindle or coolant on a cutting table (air assist is allowed on a laser), a rotary axis the machine
does not have, a lathe move off the XZ plane, a drilling cycle on a wire EDM, `wire_comp: controller`
without the cut's side, `uv_words` taper without the cut's thickness, an `O` number too big, a number that
is not one (or a feed that is not positive), an arc off its circle, a rotary turn with the tool low or
straight out of a cut, a cut after a tool change with the spindle stopped.

## Reading the result

The CLI's JSON names each setup's posted file (each tool's file, with its `tool` label, on GRBL). Open it and check the header, the work offset, the tool
list and the first moves before you report. Canned cycles posted natively follow the controller's own
retract and pass rules (a Fanuc `G73` retract is a machine parameter), so the program can differ from the
viewer's simulated path inside a cycle; the viewer shows the plain moves the cycle stands for.
