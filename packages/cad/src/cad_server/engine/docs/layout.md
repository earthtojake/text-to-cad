# Layout

A page of [the engine's documentation](../README.md). A name in bold in parentheses, such as (**Kinematics**), is another page or a named paragraph of one: the index says which.

| Module | What it is |
| --- | --- |
| `model.py` | the decorators (`out`, optional: the model's name beside the script; `name=`; `@xbf`, the `.xbf` a model is saved as), combined, one kind each, each writing its own file alone (`Model.files`); `Model` (the function, `.xbf`, `.id`, `.build` the debug seam); its id (`ids.file_id` of its `.xbf`, else of its first file), and a build's report of every model a program's call builds, wherever the model is defined; a call returning the document's handle; a child model called in a body is a sub-assembly built in the same run, its call its handle with the result in the worker, and the models a target's run ran (`BuildContext.children`); `xbf(shape, path, name=)` handing a shape over, and `step(shape, path)` (each file decorator alike) writing a file of one; `@memo` and its calls; a script's module and package (`module_of`); `paint`, `mechanism_state`, `configuration_sequence`; `read_step`, `read_xbf` |
| `api.py` | the verbs as functions, through the daemon: `export`, `snapshot`, `inspect` (the root's `cad.export`, ...), and `serve`, `status`, `stop`, which only the CLI calls (process control is the CLI's alone; deleting a document is `cli.delete`), and `build_script`, a script's models built by `Model.build()`; `Document`, the handle a model call returns (`.shape` transferred by id on first access: `result`); `hand_over`, a shape made a document in the caller and handed to the daemon; `write_shape`, a file of a shape written in the caller; `observers`, told after each build, export and snapshot what it did, as plain facts (kinds, counts, times, the worker's part, an error's type and frames): the engine counts nothing, and the server's telemetry is an observer the server appends |
| `colors.py` | a colour as the author gives it (sRGB hex, 0-255 integers, a build123d `Color`) held linear, and the way back (**Materials**) |
| `mechanism.py` | kinematics: build123d's joints harvested into AP242's links and pairs, couplings (`gear_pair`, `rack_and_pinion_pair`, `screw_pair`), mechanism states (`mechanism_state`), the document's subtree, the structure's `kinematics`, poses (forward kinematics from the ground; `posed`, an assembly copied at a state), and configuration sequences (`configuration_sequence`, a function's samples, `Timeline`: a sequence's pair values over time) |
| `build.py` | one build: load the script afresh (as Python imports it: a package's module by its dotted name), one memo run, document, element names, files: every model's that ran |
| `delta.py` | the line under the run line: a built tree's facts (`facts`: its occurrences, its world bounds -- each part's box, kept by its geometry key, measured where it decides the model's -- its parts' geometry keys and looks, and its joints, configuration sequences and warnings), worked out in the worker, and the daemon's delta of them against the build before (`delta`), kept beside each record and in the registry's |
| `previous.py` | the model's build closure on its xbf's main label (`manifest`), the release from the version beside the code and the platform, the closure made again before the body runs (`again`) |
| `document_migrations.py` | supported persisted `xbf/8` to `xbf/9` material conversion in memory (`upgrade`), a separate migration record with original build provenance retained, and unsupported/failed conversion errors that preserve saved bytes |
| `document.py` | result to XCAF (prototypes, instances, names, colours, materials, element names; a mesh face refused, `mesh_faces`), a warm build's patch of the document it kept, atomic BinXCAF save, read-back of an xbf or a foreign STEP, and a saved document's main-label strings rewritten in its bytes (`relabel`) |
| `reader.py` | what a model imports: an XCAF document described as data and assembled into a build123d tree (`read_step`, `read_xbf`); the reader process a build's STEP files are parsed in; a mesh file as data (`read_mesh`, `Mesh`); a read of a file the build writes refused (`refuse_written`) |
| `refs.py` | references to geometry: the ref grammar and the element-name pattern it reads (`ELEMENT_NAME`, kernel-free), occurrence paths, resolution by name in the latest build, for `inspect` and the viewer (**References**) |
| `step_style.py` | standard STEP surface reflectance/transparency written to styled geometry and read as an approximate PBR appearance |
| `description.py`, `describe.py`, `declarations.py`, `hulls.py` | the robot description: a document as a tree of rigid bodies in SI units (links with mass, centre and inertia, meshes, collision shapes, named frames; joints with frame, axis, limits and couplings; poses), built from the structure and the mechanism (`describe`), what a model declares for it (`body`, `frame`, `free`, `limits`, `link`, `mass`, `point_mass`), and a part's convex hulls for `cad.mujoco.decompose`, kept in the engine's cache (`hulls`) |
| `export/` | `translate` and the kind registry (`__init__`); STEP through the XCAF writer (`step`); placements and meshes from the one mesh cache (`mesh`); an MJCF and a URDF with their meshes beside them from the robot description (`mjcf`, `urdf`), and the body pairs that touch at rest, which the MJCF excludes (`contact`); a mesh file read as a document of triangles, no kernel (`mesh_file`); GLB, 3MF, binary STL (`glb`, `threemf`, `stl`); a planar document's drawing through build123d's DXF exporter, with the drawing checks (`dxf`); a motion baked into a glTF clip (`motion`); a view made a document again, for a STEP of a document held without its XCAF document and an xbf written from a STEP (`tree`) |
| `mesh.py`, `mesh_format.py` | per-part tessellation at a quarter per cent tolerance (or a GLB's, an STL's or a 3MF's own, **Mesh**), element facts and a part's whole table of them (`Topology.elements`), a part's facts as a whole (`measured`: volume, solids, box); the part buffer, its wire format and edge classes (`mesh_format`, kernel-free) |
| `parameters.py` | a model's parameters, the standard library alone: `param` (a declaration checked, its default returned), the record of a load's declarations with where each default is spelled (`recording`, `Declared`), a model's rows (`rows`), the document's record (`record`, `recorded`), the page's view of them (`served`), and what a Save checks and writes (`changes`, `standing`, `spelled`, `splice`); the server's own half is its `parameters.py` (**Parameters**) |
| `serve.py` | HTTP: structure JSON and one binary buffer per part; each part's facts by geometry key, measured in batches (`FactCache`, `Server.measure`), and its face table by the same key (`Server.tables`, `Server.table`); the meshing pool and its queues (`Mesher`); a STEP read in a reader process, held by its bytes |
| `windows_spawn.py` | on Windows, the spawn pools' processes in the base started by its real interpreter, told the environment (`__PYVENV_LAUNCHER__`): a venv's `python.exe` is a launcher, which never passes the pool's handles on (CPython's bpo-35797) |
| `snapshot.py` | `cad <type> snapshot`: one dispatcher by suffix -- a document, a mesh file, a robot or a DXF drawn by OCCT (`render/`), or a KiCad board or one sheet of a KiCad schematic drawn flat (`render/board.py`, `render/schematic.py`), into a PNG; a script's model drawn from its worker's memory |
| `formats/` | the files the stills draw that are not documents, each read into a structure and part buffers: STL (numpy), 3MF (zip + XML), GLB (OCCT's glTF reader, textures and all; and numpy's, for a conversion: `gltf`), URDF/SRDF (the stills' view of the engine's one read of each, `urdf_source`: numpy frames, the shapes the stills draw, forward kinematics held to a golden), DXF (group codes, flattened as the viewer's pane draws it); a KiCad board (`kicad/`: its S-expressions read by the standard library alone into an index of parts, pads, tracks, vias, pours, holes, outline and nets, its references, and the plot payload the page and the flat still draw); a KiCad schematic (`kicad/schematic*.py`: its hierarchy read from its project's root into sheets, symbols and pins, wires, buses, labels, and the nets KiCad's connection graph makes of them, its references, and its plot payload, every sheet a page) |
| `mesh_uri.py` | a robot description's mesh reference: its URI scheme (a drive letter is none: `C:/x` is a path) and the local file it names (`file:` read by the platform's `url2pathname`, a `file://HOST/` share a UNC path on Windows and no local file elsewhere); the standard library only, so the URDF reader and validator, the viewer's robot payload and the stills (`formats/robot.py`) all read one the same way; a `package://` one in the ROS package the description is in (`package_file`) |
| `robot_model.py` | the one articulation every reader of a robot description makes (`Articulation`: each link's rest frame, its `Visual`s, the `LinkJoint`s with their mimics and four-bars, the named poses, an SRDF's home, the facts as written) and the `Dialect` a consumer reads by where the viewer's payload and the stills have read a detail differently (its refusals' words by code, whether it reads the facts as written); matrices as lists, the standard library alone |
| `urdf_source.py` | a URDF (and an SRDF's group states over it), read once into `robot_model`'s articulation: the stills (`formats/robot.py`) and the viewer's payload (the server's `robot_payload.py`) are two views of that read; the standard library alone |
| `render/` | the stills drawn by OCCT from the engine's meshes: a document held and drawn, and the render process per served document and per file (`service.py`, the library's; the daemon's side of it is the server's `renders.py`); the scene (`occt.py`); a DXF drawn in the 2D look (`drawing.py`); a KiCad board's flat still, painted with Pillow from its plot (`board.py`), and a schematic sheet's (`schematic.py`); the viewer's Explode, ported (`explode.py`); a part's buffer as OCCT shapes (`shapes.py`); the headless OpenGL context per platform (`context.py`) |
| `daemon.py`, `worker.py`, `client.py` | one daemon for the device (its engine folder), one warm worker per model script and Python, at most one per core alive (`supervisor.py`), connect-or-start (an installation's engine, never one of the library's own environment), a hold; a worker's memory cap. The daemon is the server's; the worker and the client are the library's, which a model's process and its worker run where only the library is installed |
| `supervisor.py`, `services.py` | the server's one supervisor of every process the daemon starts (`Supervisor`, `Process`), and their declarations (`WORKER`, `RENDER`, `CHECKS`): **Services** |
| `checks.py`, `checks_runner.py` | the manufacturing checks the engine measures: their kept results (`Checks`, `Disk`) and the pool of checks processes (`Pool`); a check's life, from asked to answered or stopped (`Runner`): **Document types and integrations** |
| the server's `parameters.py` | `set`: a model's parameters written into its script and its last run built again, refused by one word of a closed set (`Setting`), and the run each worker built last, kept to build again (`ran`): **Parameters** |
| the server's `viewer/bundle.py` | a file's view bundle, a share's view: its page's reads asked of the page's own application, in process, gathered beside the folder and moved into it as files with a manifest (`write`, `cad share`'s step, `{"op": "bundle"}`): **View bundle** |
| the server's `sharing.py`, `cli/share.py`, `cli/import_.py` | `cad share`: a share's names and links, a view bundle's files as its manifest lists them, a shared file's files (a model's `.xbf` and those of the build closure it holds, under its files' root; a file's), the `cad-share/2` packs of the ones a share lacks, the service's API with `urllib` in the command's own process, a share's zip read and written into a folder, a share's link as this computer's copy of it, and what is kept -- the agreement, the setting, each share and import in its file's entry of the library, and in each shared file's folder of the cache its bundle, where its files live and its lock -- written by the running server for the command where one answers (`{"op": "share"}`); the commands (`cli/share.py`, and `cli/import_.py`, `cad import`): **Sharing** |
| `renders.py` | the server's side of the render processes: a served document's picture, its version sent first, the process leased from the supervisor |
| `display.py` | the engine's X display on Linux, which a render process is started with (`Service.draws`) and a worker told with an export that draws: the daemon's own `DISPLAY`, else an Xvfb it starts at the first picture and stops with it, else none |
| `frames.py` | the frames every process of the engine's speaks to the daemon, read and written: the library's, the standard library alone (**Services**, the protocol) |
| `contract.py` | the worker contract the library and the server both state (`CONTRACT`: the worker protocol's number, the document format, OCP's major.minor), the Python an order comes from (`interpreter`), the one line another contract is refused in (`refusal`) and the update notice of another release (`notice`): **Running a model**; what measures a manufacturing check (`measuring`, from `_measuring.py`, of the standard library alone, which `cad.engine` takes as it is imported) |
| `places.py` | where things are, for every process alike, with the standard library alone: the user's one state folder and cache folder (`state_dir`, `cache_dir`), the engine folder and its door, lock and port file (`engine_dir`, `folder_refusal`, `lock`), the installation a process belongs to (`installation`, the base's marker as `HOME`) and the current one the clients of 0.11.11 and earlier start (`current`), and how a process of the engine's is started (`windowless`, `detached`, `bytecode`, and the kernel environment, `kernel`, which the server makes as `KERNEL`) |
| `said.py` | the words a build, an export and an inspection are said in: the run line and what is under it (`describe`, `reported`), a file written (`written`, `given`), what a robot file holds (`robot`), a size and a measure (`size`, `number`); a model's process says them, and the commands say the same |
| `weights.py` | what a document weighs as its robot description weighs it, for `inspect`: the description's **Mass** rule over the engine's volumes, with no kernel -- each part's mass, its point masses, which is declared and which computed (`Weights.said`), and the description's refusal in its words |
| `door.py` | how a client reaches the daemon on POSIX: the door, a named pipe, and a pair of pipes per connection (**The door**) |
| `progress.py` | where a build is: the engine's stages heard where they begin, each body a model's body runs by name, the frames, and the terminal's bar |
| `atomic_replace.py` | the one rename every written file is moved into place with: the library's bounded Windows retry, kept in the engine |
| `state.py` | the one owner of every write under the user's state and cache folders (`Folder`), the lock a read and a write of one file are held under (`lock`), a file's version (`file_version`), the user's page token (`State.token`, `put_token`) and the engine's record (`State.engine`, `put_engine`: its rolled port); the server's |
| `library.py` | the library file of the state folder (`Library`: the project folders and the files a person opened or pinned, read, changed under one lock, and what an earlier release recorded carried into it, `migrate`) and the note the cache keeps of a file (`Notes`: its count and picture, valid for one version of the file); the server's (**Document lifetime**) |
| `cli.py` | the verbs as commands, the server's: the operations `export`, `snapshot` and `inspect` (each type's, `cad <type> <operation>`), and `serve`, `status`, `stop`, `server` (`parser_for`, `run`; also `python -m cad_server.engine VERB`), each said in `said`'s words |
| `kernel/` | the memo (`memo.py`), maker history (`history.py`), element naming (`trace.py`), deterministic kernel settings (`determinism.py`) |
