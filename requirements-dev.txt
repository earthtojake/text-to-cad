# Repo-source development environment: running tests and tools from a checkout.
#
# The editable packages below are what every pin of this release resolves to locally:
# sync-version.mjs stamps their pyproject.toml files from VERSION, so the editable installs report
# exactly the pinned version. Installing a skill's requirements.txt WITHOUT this file fetches the
# last published release from PyPI instead of the checkout -- this file is the development door.
# The library with its build123d extra: this environment runs models itself, so it is its own base
# environment and the server makes none (packages/cad-server/src/cad_server/_internal/base.py). And with
# its trimesh extra, so `cad <type> check --process` measures in this environment and the server makes no
# environment of cad[trimesh] for it (packages/cad-server/src/cad_server/_internal/integration_env.py). The
# netgen extra is not here: a stress study (`cad <type> fea`) is the fea job's, which installs it with
# CalculiX (scripts/test/test-fea.sh); without it, here, the command makes cad[build123d,netgen].
--editable ./packages/cad[build123d,trimesh]
--editable ./packages/cad-server
--editable ./packages/cad-mcp

# pip installs the Python; it cannot build the JavaScript that ships beside it.
# packages/cad-server/src/cad_server/_runtime is gitignored and produced by
# `scripts/bundle/bundle.sh`, so run that once after installing this file --
# without it the packaged Viewer and the CAD app have no client to serve; the server
# names this command when it finds none.

# The packages' own runtime dependencies come with the editable installs above: the library's
# (numpy), its build123d extra's (build123d, cadquery-ocp-novtk, bd_materials, threejs-materials,
# matplotlib, shapely, ezdxf, pillow) and its trimesh extra's (trimesh, rtree, scipy, networkx), and the
# server's (uv, ezdxf, pillow).
