# Migration: legacy live concepts → state primitives

The strategy is **parallel build, incremental port, delete last**. The kernel
and bridges land beside `wire/src/live/` with no consumer changes; consumers
port one subsystem at a time with their existing test suites as parity gates;
legacy classes are deleted only when nothing constructs them.

## Concept mapping

| Legacy (in `wire/src/live/` unless noted) | Fate | Replacement |
|---|---|---|
| `LiveStateSource` used directly by feature/runtime code | migrates | `cell` (in-memory truth) or `query.settle` (external truth), published via `expose` |
| `LiveStateSource` as wire-edge patch publisher | **stays** | reused inside `expose` |
| `ComputedLiveState` | deleted | `query` — `compute`→`fetch`, `invalidate()`→pokes/`invalidate()`, `refresh(mutationId)`→`refresh({mutationIds})`, `debounceMs`/`revalidateIntervalMs`/`isEqual` → same options; demand gating and refresh collapse are kernel behavior |
| `BatchedLiveState` (`microtaskScheduler`) | deleted | turn coalescing — synchronous writes coalesce automatically |
| `BatchedLiveState` (`timerScheduler(ms)`) | deleted | `expose` per-state `debounceMs` (wire-edge windowing) or `query.debounceMs` (source-edge) |
| `bindMachineToLiveState` (`machine-binding.ts`) | deleted | `cell`/`derived` projections exposed with `expose` |
| Hand-written `LeasedLiveModelProvider` implementations | deleted per port | generated by `expose` |
| `createResourceLiveModelHost` (`mutations/resource-host.ts`) | **deleted (done)** | `expose` over a `family` (the `acquire` option becomes the family factory; `states` bindings become family-member nodes; `ctx.settle(name, cursor)` → `ctx.observed(name, revision)`) |
| `createLiveModelHost` (`mutations/host.ts`) registry of instances | **deleted (done)** | `family` of `cell`s + `expose`; `instances(partialKey)` enumeration → an explicit index `cell`/`derived` where actually needed |
| `mutations/group.ts` optimistic recipes (`ctx.produce`) | **deleted (done)** | [`optimistic`](./02-primitives.md#optimistic) primitive + shared reducers ([03, example 4](./03-composition.md#worked-example-4-optimistic-overlay-client-side)) |
| `MutationResultCache` (moved to `state/bridge/result-cache.ts`) | **stays** | reused by `expose` |
| `createLiveModelReplicaCache`, `ReplicaState`, stores, gap handling | **stays** | wrapped by `remote`; direct consumer use migrates to `remote` |
| `resourceCachedLiveSource`, `follower.ts` | **stays** | transport plumbing under the bridges |
| `live/protocol/` (cursors, snapshots, updates, `LiveSource`) | **stays** | unchanged wire format |
| `live/log/`, `live/event-stream/`, `live/job/` | **stay** | out of scope by design |
| Planned `createLiveQuery`/poke-bus/`useLiveQuery` (tasks-projects plan, phase 0) | absorbed | `family`+`query`+`expose`; poke bus lands as `pokeChannel` producers; `useLiveQuery` = renderer adapter over `remote` |

Consumer-side patterns that dissolve (outside `packages/wire`):

- `TreeResource`'s lane/resync bookkeeping (~200 lines) → `query` semantics;
  its model code survives as pure functions
  ([03, example 2](./03-composition.md#worked-example-2-file-tree-dynamic-deps-cell--query-join-settle)).
- `RepositoryResource`'s `ComputedLiveState` quartet + invalidation fan-out →
  `query` family + channel subscriptions
  ([03, example 1](./03-composition.md#worked-example-1-git-runtime-query-family-pokes-lanes)).
- Renderer stores' manual replica/lease juggling and fetch-on-mount plumbing →
  view-scope-owned `pin`s + the MobX atom/reconciler bridge
  ([03, Renderer integration](./03-composition.md#renderer-integration-mobx));
  stores become passive reconcilers of pinned models.

## Semantics that must not regress (parity checklist)

Carried over 1:1 — each has either an existing legacy test to keep green or a
new state test under `wire/src/state/`:

- [x] Demand gating: unobserved+dirty does no work (`query.test.ts`,
      `bridge/expose.test.ts`)
- [x] One-in-flight + one-queued refresh collapse; `refresh()` returns the
      cursor/revision containing its result
- [x] Equality/no-op suppression at both source (`isEqual`) and wire edge
      (Immer empty-patch check in `LiveStateSource`)
- [x] Debounce and revalidate-interval timers, `unref`'d, cleared when
      unobserved
- [x] Mutation idempotency via `mutationId` result cache
- [x] Settled cursors: mutation response resolves with cursors; client
      `settled` promise fulfills on tagged update (`replica/instance` tests)
- [x] Error atomicity: a throwing derived/query leaves state recoverable
      (`kernel.test.ts`, `query.test.ts`)
- [x] Lease acquire/release pairing incl. failure paths
      (`resource-host` acquire tests)
- [x] Replica gap → resync; persistent-store seed then live catch-up
      (`bridge/roundtrip.test.ts`)

New behavior, to be flagged in the PR that enables each:

- Turn batching (≤1 microtask latency; strictly fewer publishes)
- Glitch-freedom across formerly-independent states joined by a `derived`
- `mutationIds` propagating through derivations (previously only same-state)
- `settle` write-through (previously every mutation path re-read)
- Family linger (bounded warm retention after last observer)
- `optimistic` rollback-by-projection (previously baked-in patches needed
  explicit undo) and its resync/TTL pruning
- Pin-based renderer demand (fetch at boundary instead of render; unpinned
  render reads return `undefined` + dev warning instead of silently fetching)

One audit before enabling equality gating as default: no consumer may rely on
publishes as heartbeats (`LiveStateSource.replace` today bumps the sequence for
*changed* values only — but `ComputedLiveState` with `isEqual` never
publishes equal results, so exposure is limited to direct `LiveStateSource` users).

## Order of work

Matches the incremental plan (each step shippable, tested, no consumer
breakage):

1. **Kernel** (`state/core/`): graph, turns, tracking, status/mutationId
   folding, `cell`/`derived`/`family`/`observe`/`peek`/`batch`. Sync-only,
   exhaustively tested with fake clocks.
2. **`query` + `pokeChannel`** (`state/`): port
   `ComputedLiveState` semantics as options; add settle with lane ordering and
   the stale-fetch guard.
3. **Bridges** (`state/bridge/`): `expose` (over `LiveStateSource` +
   `MutationResultCache`), `remote` (over `createLiveModelReplicaCache`). Contract
   tests: a round-trip expose→transport→remote harness. Alongside:
   `optimistic` and `pin`/`prefetch` (kernel-level compositions used by the
   client side of the bridge).
4. **First customer: git runtime** — mechanical `ComputedLiveState`→`query`
   port; existing git runtime tests as parity gate.
5. **DB-backed models** — execute the tasks/projects LiveQuery plan on the
   kernel (its Phase 0 *is* steps 1–3), including the renderer bridge: MobX
   atoms + reconciler, view-scope-owned pins (view scopes gain an owned
   kernel `Scope`; `defineViewScope` definitions declare their data pins).
6. **File tree** — the hard port: dynamic deps, settle, shared reducers, and
   the `optimistic` overlay replacing `mutations/group.ts` recipes.
7. **Deletions**: `ComputedLiveState`, `machine-binding`,
   `resource-host`, `host` (registry flavor), hand-written providers; update
   `packages/wire/docs/live/*.md` and `agents/conventions/` pages.

## Proposed folder layout (implementation, future steps)

```text
packages/wire/src/state/
  README.md, 01…05-*.md      — these docs
  core/
    node.ts                  — node representation, revisions, snapshots
    scheduler.ts             — turn scheduling, batch()
    cell.ts  derived.ts  family.ts  observe.ts
    kernel.test.ts family.test.ts
  query.ts                   — query node (pokes, settle, lanes, timers)
  query.test.ts
  poke.ts                    — pokeChannel
  optimistic.ts              — optimistic overlay (cell + derived + snapshot metadata)
  optimistic.test.ts
  pin.ts                     — pin/prefetch demand helpers (observe + scope)
  pin.test.ts
  bridge/
    expose.ts                — reactive → LeasedLiveModelProvider
    remote.ts                — replica → reactive family
    expose.test.ts roundtrip.test.ts
  testing.ts                 — state-test helpers
  index.ts
```

`core/` stays free of any `live/` import; only `bridge/` may import from
`live/` (protocol, `LiveStateSource`, replica, result cache). That keeps the kernel
usable for purely local state and enforces the transport boundary
structurally.
